# MDX-lite 组件 Demo

本文件展示 Git Leaf 当前支持的 6 个 MDX-lite 组件。这里的数字和流程是演示数据，只用于检查视觉效果，
不作为业务事实源。组件写法、字段和边界见 [mdx-lite-guide.md](mdx-lite-guide.md)。

本文件是 Git Leaf 的完整开发和视觉回归样例。目标内容仓库可以维护面向自身读者的精选 Demo，但实现能力、
组件语法和安全边界始终以本仓库的代码、测试和参考文档为准。

| 组件 | 展示重点 |
| --- | --- |
| `DataTable` | 数据表、宽表、结构化明细 |
| `Timeline` | 里程碑、处理进度、风险状态 |
| `Chart` | 折线、柱状、分组柱状、堆叠柱状、柱线混合等阅读型统计图 |
| `DecisionBox` | 决策、理由、代价、重评条件 |
| `MetricGrid` | 少量核心指标摘要 |
| `FlowDiagram` | 主流程、系统链路、AI Agent 介入点 |

## 1. DataTable

适合比普通 Markdown 表格更需要阅读舒适度的数据明细。Git Leaf 会根据复杂度决定是否显示搜索、冻结首列、
粘性表头和复制 CSV。

<DataTable title="文档治理字段样例" columns="field,purpose,required,example,note">
```csv
field,purpose,required,example,note
title,文档标题,yes,Git Leaf 系统架构,用于页面标题和搜索识别
domain,所属领域,yes,ai,帮助 AI Agent 判断事实归属
type,文档类型,yes,architecture,决定文档维护方式
owner,维护人,yes,maintainer,填写负责维护该文档的角色或账号
last_updated,最近维护日期,yes,2026-07-05,使用 YYYY-MM-DD
source,来源,no,git-leaf,说明材料来源或维护系统
canonical,权威标记,no,false,true 时才能作为当前权威依据
ai_snippet,AI 摘要,yes,[Demo] ...,帮助搜索和路由
change_log,变更记录,conditional,,canonical true 文档必须维护
```
</DataTable>

## 4. DecisionBox

适合把关键决策放在正文附近，让读者先判断当前结论是否可引用。

<DecisionBox title="Git Leaf 不做独立文档站" status="accepted" owner="maintainer" source="architecture.md">
```csv
label,value
决策,"Git Leaf 是本地 Git 文档工作台，不是部署到线上长期访问的 docs site。"
理由,"同事主要需要预览、编辑、定位当前仓库文档和切换 worktree；本机服务能减少额外入口和维护成本。"
代价,"Git Leaf 不提供远程访问、账号系统或公网知识库能力。"
重评,"如果未来需要长期公网访问、统一账号或跨团队文档门户，再评估独立部署形态。"
```
</DecisionBox>

## 5. MetricGrid

适合在报告、复盘或说明文档开头给出少量核心指标。它不替代详细表格，也不做复杂筛选。

<MetricGrid title="Git Leaf 当前能力摘要">
```csv

本机访问,可编辑,,桌面与 CLI/Web 都只监听 localhost,check
编辑范围,任意分支,,Detached 首次写入前自动创建保护分支,good
桌面入口,Electron,,打开 App 后选择本机 Git 仓库,good
```
</MetricGrid>

## 检查重点

- 6 个组件都应该正常渲染，不能显示 `MDX 组件渲染失败`。
- `Chart` hover 时应显示同一月份下的多指标 tooltip。
- `FlowDiagram` 应渲染为静态 SVG。
- 详细语法和新增组件策略以 [mdx-lite-guide.md](mdx-lite-guide.md) 为准。
